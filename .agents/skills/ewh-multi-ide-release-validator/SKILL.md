# Everywhere Multi-IDE Release Validator

Use this skill whenever any extension code, configuration, version, or workflow in `Everywhere-DeepSeek-Harness` is created, modified, or prepared for a Git commit, push, tag, or release.

## Objective

Prevent release pipeline breakages in CI/CD across all 4 supported IDEs (**VS Code**, **Visual Studio 2022**, **IntelliJ IDEA**, and **Eclipse IDE**).

---

## Pre-Push & Release Checklist

Before pushing or tagging any release, perform the following verifications:

### 1. Eclipse IDE (Tycho OSGi & p2 Site)
- **OSGi Qualifier Contract**:
  - In `eclipse/pom.xml`, if `<version>` ends with `-SNAPSHOT` (e.g., `1.0.0-SNAPSHOT`), `eclipse/META-INF/MANIFEST.MF` **MUST** declare:
    ```properties
    Bundle-Version: 1.0.0.qualifier
    ```
    *(Never use a plain `1.0.0` without `.qualifier` for SNAPSHOT builds, as Tycho will fail `validate-version`).*
- **p2 Repository Structure**:
  - Ensure `eclipse/pom.xml` contains the `tycho-p2-repository-plugin` with `assemble-repository` and `archive-repository`.
  - In `.github/workflows/release.yml`, ensure the p2 artifacts point to `eclipse/target/repository` and `eclipse/target/*.zip` (and never hardcode non-existent submodules like `eclipse/repository/target/repository`).
  - Ensure landing page `eclipse/repository/index.html` and `.nojekyll` are copied to the deployed update site directory.

### 2. VS Code Extension
- **Version Alignment**:
  - `vscode/package.json` version must be bumped (e.g. `1.2.9`).
  - Run packaging test if needed:
    ```sh
    cd vscode && npm test
    ```
- **Asset Links**:
  - Verify `icon` in `vscode/package.json` points to an existing file (e.g. `assets/icon/icon.png`).
  - Verify SVG icons in `vscode/media/` and `vscode/assets/icon/` have correct, responsive `viewBox` coordinates without clipping.

### 3. IntelliJ IDEA Plugin
- **Plugin Descriptor**:
  - Ensure `intellij/src/main/resources/META-INF/plugin.xml` has valid `<id>`, `<name>`, `<version>`, and compatibility ranges (`<idea-version since-build="..." />`).
- **Gradle Verification**:
  - Verify `gradlew` permissions (`chmod +x intellij/gradlew`).

### 4. Visual Studio 2022 Extension (VSIX)
- **Manifest IDs**:
  - Check `visualstudio/Everywhere/source.extension.vsixmanifest` for consistent ID and version.
  - In `visualstudio/publishManifest.json`, ensure IDs do not contain disallowed dots where hyphens are required.

### 5. GitHub Actions Release Workflow (.github/workflows/release.yml)
- **Path and File Match Check**:
  - Every path referenced in `actions/upload-artifact` and `softprops/action-gh-release` must resolve to real output directories generated by the build steps.
  - Test glob patterns before pushing:
    - Eclipse: `eclipse/target/*.zip`, `eclipse/target/*.jar`
    - IntelliJ: `intellij/build/distributions/*.zip`
    - VS Code: `vscode/*.vsix`
    - Visual Studio: `visualstudio/**/*.vsix`

## Automated Validation Command

Run this one-liner check in repository root before pushing:

```sh
python3 -c "
import os, sys

# 1. Eclipse MANIFEST.MF vs pom.xml
with open('eclipse/pom.xml') as f:
    pom = f.read()
with open('eclipse/META-INF/MANIFEST.MF') as f:
    mf = f.read()

if '1.0.0-SNAPSHOT' in pom and 'Bundle-Version: 1.0.0.qualifier' not in mf:
    sys.exit('ERRO: eclipse/META-INF/MANIFEST.MF deve conter Bundle-Version: 1.0.0.qualifier para builds SNAPSHOT!')

# 2. Release workflow path sanity
with open('.github/workflows/release.yml') as f:
    wf = f.read()

if 'eclipse/repository/target/repository' in wf:
    sys.exit('ERRO: release.yml contem caminho invalido eclipse/repository/target/repository!')

print('✅ Todas as validacoes de release passaram com sucesso!')
"
```
